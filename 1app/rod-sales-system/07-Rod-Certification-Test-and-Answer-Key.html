Part B — Practical tests

1. Discovery role-play

Scenario: A roofing owner misses calls while on job sites, uses a paper calendar, and says leads sometimes call a competitor.

Rod must:

  • [ ] Set a clear agenda.
  • [ ] Ask situation, problem, implication, and need-payoff questions.
  • [ ] Quantify volume/impact without inventing numbers.
  • [ ] Establish a relevant baseline and separate savings from revenue opportunity.
  • [ ] Show one transparent value scenario with assumptions.
  • [ ] Identify variables outside 1APP's control.
  • [ ] Identify the decision-maker and current systems.
  • [ ] Recommend no more than three initial automations.
  • [ ] Avoid promising results.
  • [ ] Agree on a dated next step.

2. Quote-builder test

Use https://use1app.com/quote-builder/, the included 1APP-Quote-Builder.html, or the printable worksheet in Document 09.

Rod must:

  • [ ] Create a correct client/quote record.
  • [ ] Choose the smallest useful automation set.
  • [ ] Separate the four commercial price categories: one-time setup, monthly recurring service, usage/pass-through charges, and optional/custom work; show HST separately.
  • [ ] State delivery as starting after Ready-to-Build.
  • [ ] State trial scope and success measure.
  • [ ] Record client responsibilities and exclusions.
  • [ ] Route the draft to Tony and Justin instead of sending it directly.

3. Handoff test

Rod completes the onboarding/handoff for the roofing scenario.

Critical fail if:

  • A selected automation is missing requirements.
  • Copy, hours, ownership, stop logic, or escalation is undefined.
  • A password or secret is recorded.
  • Quote and handoff scope conflict.
  • A launch date is promised before technical acceptance.

4. System navigation

  • [ ] Create/deduplicate a contact.
  • [ ] Create an opportunity in the correct pipeline.
  • [ ] Add problem statement, source, owner, and next action.
  • [ ] Log a call outcome.
  • [ ] Create a task.
  • [ ] Record quote ID/version and trial dates.
  • [ ] Show that prohibited admin/billing controls are unavailable.

5. 90-second explanation

Rod explains 1APP to a contractor, then handles:

  • “We already have software.”
  • “How much does it cost?”
  • “Can you guarantee more jobs?”
  • “Can you connect to our current system?”

6. Automation value and ROI practical

Rod receives three mock client cases and must:

  • [ ] Identify the symptom, root problem, and smallest useful automation.
  • [ ] Explain the financial mechanism without feature dumping.
  • [ ] Select the correct baseline and outcome measures.
  • [ ] Calculate the value scenario accurately.
  • [ ] Distinguish revenue from gross profit and capacity from payroll savings.
  • [ ] State assumptions, attribution limits, and variables outside 1APP's control.
  • [ ] Give a buyer-safe explanation without guaranteeing a result.

Automatic retry: invented inputs, double-counted value, unsupported causation, or any guaranteed revenue/performance claim.
